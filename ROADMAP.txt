2. PRODUCT STRATEGY
==================================================================

Order of value:
  Core product -> real-world usage and validation -> monetization validation -> AI / Pro+

Why: real Claude API use creates recurring cost. That cost should only be taken on after
there is evidence that people use Bravune and are willing to pay for it.

AI architecture (ALREADY BUILT, stays in the code with its tests):
  User Request -> AI Engine -> AIMixPlan / MixRequest -> Mix Engine -> UnifiedQueue -> Player

Real Claude integration, AI features and AI monetization (LATER, Workstream 6):
  - Not a blocker for any other work in this roadmap.
  - No Anthropic API key is needed to finish the core product.
  - Not required for the first usable or releasable version.
  - No AI API cost is added to normal Bravune usage. Claude is only called when a
    Pro+ user explicitly asks for an AI feature.
  - AI is intended to be a Pro+ monetization layer.

Provider work runs in PARALLEL. A provider blocked on credentials (for example Navidrome)
never blocks the rest of Bravune development.

------------------------------------------------------------------
SPOTIFY: ON HOLD for paid use (owner, 2026-10-01); a priority provider for a non-commercial
build only (owner, 2026-10-02, see PRIORITY PROVIDERS)
------------------------------------------------------------------
Spotify is ignored completely until Bravune has about 250,000 active users.
No real Spotify validation, no Spotify credentials or dashboard setup, no preparation work,
and no business plan that depends on Spotify.

WHY (from Spotify's own current documents, effective 15 May 2025, reviewed 2026-09-30):
  1. Controlling Spotify playback through the Web API counts as "Streaming" in Spotify's
     Developer Terms. Spotify's Compliance Tips list the /me/player/play call as a streaming app.
     An app with any streaming functionality is a "Streaming SDA" regardless of its other features.
  2. Spotify's Developer Policy (section IV) does not permit commercial use of a Streaming SDA:
     no selling it (also not as part of a bigger product), no in-app payments, no advertising.
     Spotify's examples allow selling only apps WITHOUT streaming, such as a playlist manager.
     A paid Bravune with Spotify playback control therefore cannot rely on Spotify.
  3. Development Mode (changed February 2026) is meant for personal, non-commercial projects:
     the app owner needs Spotify Premium, one Client ID per developer, at most 5 authorized users.
  4. Extended quota (more than 5 users) is only offered to registered organizations with about
     250,000 monthly active users. Individuals are not accepted.
  5. Other Policy lines are unclear for Bravune and would need Spotify's clarification: no
     product "integrated with streams or content from another service" (Bravune combines
     providers), no mixing or overlapping of Spotify audio (Spotify's examples describe DJ-style
     mixing, which Bravune does not do), and no feeding Spotify content to AI models.

UNTIL WHEN:
  Reopen only when ALL of these are true:
    - Bravune has about 250,000 active users, AND
    - there is a registered business entity that can apply for extended quota, AND
    - Spotify has approved it.
  Reaching 250,000 users alone does NOT make commercial Spotify use allowed. The ban on
  commercial use of streaming apps stays in force. Commercial use would still need a written
  "Separate Agreement" signed by Spotify, and Spotify has published no application path for it.
  Spotify can change its terms at any time, so re-read them before reopening.

WHAT STAYS:
  - The existing Spotify code and its mock tests stay in the project untouched. Spotify lives
    in its own provider module and can be excluded from any build without changing
    UnifiedQueue, Player or Mix Engine.
  - Paid builds must not contain Spotify functionality. If Spotify is ever used it belongs in a
    separate, non-commercial build.
  - Real-world provider revenue is planned around Local Music, Subsonic/Navidrome and, after its
    terms are checked, Apple Music.

Sources: developer.spotify.com/policy, /terms, /compliance-tips,
         /documentation/web-api/concepts/quota-modes,
         /blog/2026-02-06-update-on-developer-access-and-platform-security
